# WriterTools 日志文件格式规范 v1.0（WTL, WriterTools Log）

> **状态**：v1.0 定稿（2026-10-20），首版实现依据。
> **核心承诺**：本格式**只增不删**。任何后续版本只能新增可选字段、新增事件类型、新增枚举值，**不得删除、改名、改变已有字段的类型或语义**。所有 v1.x 读者必须能读懂 v1.0 文件；所有 v1.0 读者遇到 v1.x 新内容时按第 8 节的兼容规则降级（忽略未知信息或只读打开），绝不破坏、不丢数据。
>
> 本文中的"必须 / MUST""不得 / MUST NOT""应该 / SHOULD""可以 / MAY"按 RFC 2119 的强度理解。

---

## 1. 概述

一个作品 = 一个日志文件（`*.wtlog`），内容是 **UTF-8 编码的 JSON Lines（每行一个 JSON 对象）**，追加写入、永不改写历史行。文件本身既是正文的历史，也是逐字符的输入档案：

- 每一次插入、删除、替换、输入法组合过程都作为事件按时间顺序追加；
- 每行带哈希链（`prev` / `hash`），任何一行被删、被改、顺序被打乱都能被检测出来；
- 定期写入 `snapshot` 快照事件（含该时刻完整正文），即使前端重放逻辑出错也能从快照恢复；
- 删除的文字**完整保存在事件的 `deleted` 字段里**，删掉的东西永远可追回；
- 一个文件即一个作品，可单独导出、备份、恢复；作品之间互不依赖。

### 1.1 文件命名与类型

| 项目 | 约定 |
| --- | --- |
| 扩展名 | `.wtlog`（推荐导出名 `作品名-<docId 前 8 位>.wtlog`） |
| 内容 | UTF-8（无 BOM）、LF (`\n`) 换行、JSON Lines |
| MIME | `application/x-writertools-log` |
| 导入兼容 | 允许导入 `.wtlog`；为方便手工检查，`.wtlog.jsonl` / `.jsonl` 也可按本格式解析（内容相同） |
| 大小写 | 事件类型、枚举值一律小写；哈希值一律小写十六进制 |

### 1.2 设计原则

1. **追加写（append-only）**：日志只允许在末尾追加新行；任何工具不得修改、删除、重排已有行。
2. **只增不删**：格式演进只允许新增，见第 8 节。
3. **可验证**：每行哈希链自证完整；可选的备份清单提供外部锚点，检测整段截断/重写。
4. **可恢复**：删除内容留档；快照留正文；多副本存储（应用层职责）；损坏时可按"最长有效前缀"抢救。
5. **自包含**：不依赖数据库、不依赖应用内部状态即可还原正文与输入历史。
6. **明文优先**：v1.0 不加密（见第 11 节未来预留）；用户明确知情。

## 2. 文件结构

```
第 1 行    header 事件（type = "doc.init"，seq = 0）
第 2..N 行 普通事件（seq 递增，连续，无空洞）
```

- 每个文件**必须**恰好有一个 header，且位于第 1 行、`seq = 0`、`type = "doc.init"`。
- `seq` 从 0 开始、每行 +1，**不得有空洞、重复、乱序**。
- 最后一行**应该**以 `\n` 结尾（读取时容忍缺失）。
- 空行**不得**出现（读取时忽略空行并打警告，但视为轻微损坏，不影响哈希链校验）。
- 单行大小**应该** ≤ 256 KiB；大段文本（粘贴、恢复）必须拆成多个事件（见 6.2）。

## 3. 事件信封（Envelope）

每个事件（含 header）都是如下对象。**所有事件都必须有这些字段**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `seq` | 整数 ≥ 0 | 行号，从 0 连续递增 |
| `id` | 字符串 | 事件唯一 ID，`^[A-Za-z0-9_-]{8,64}$`；实现用小写 UUIDv4 |
| `ts` | 字符串 | 事件时间，RFC 3339 UTC，毫秒精度：`2026-10-20T15:32:04.123Z`。**必须**带 `Z`，不存本地时区偏移（时区信息放事件 data 或 session） |
| `type` | 字符串 | 事件类型，`^[a-z][a-z0-9]*(\.[a-z][a-z0-9]*)*$`；核心类型见第 6 节；自定义类型必须以 `x.` 开头 |
| `affects` | `"text"` 或 `"meta"` | **必须显式声明**：该事件是否改变正文。`"text"` 的事件按 seq 顺序作用于正文；`"meta"` 不影响正文 |
| `prev` | 字符串 | 前一行事件的 `hash`；`seq = 0` 时为空字符串 `""` |
| `hash` | 字符串 | `sha256:<64位小写十六进制>`，计算方式见第 4 节；不参与自身的哈希计算 |
| `data` | 对象 | 事件载荷；无载荷时为 `{}` |

header 事件额外**必须**有：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `magic` | 字符串 | 固定为 `"writertools-log"` |
| `format` | 字符串 | 文件格式版本，`主版本.次版本`，v1.0 为 `"1.0"` |

**未知字段**：允许存在于任意层级（信封或 data 内）。读者**必须忽略**未知字段做展示/重放，但任何未来的压缩/重写工具**必须原样保留**它们（v1.0 禁止重写历史行，见 4.4）。

### 3.1 header 事件 data 字段

`type = "doc.init"`，`affects = "meta"`：

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `docId` | 字符串 | 是 | 作品全局唯一 ID（UUIDv4 小写）；**永不变更**，与标题、文件名无关 |
| `title` | 字符串 | 是 | 初始标题（可为空字符串，显示时回退"无题"） |
| `createdAt` | 字符串 | 是 | 创建时间，ISO UTC，同 `ts` |
| `app` | 对象 | 是 | 写出该文件的应用：`{ "name": string, "version": string }` |
| `device` | 对象 | 否 | `{ "platform"?: string, "userAgent"?: string, "tz"?: string }` |
| `settings` | 对象 | 否 | 文档级初始设置；键值参见 6.14（未知键忽略） |

## 4. 规范化 JSON 与哈希链

### 4.1 规范化 JSON（Canonical JSON）

计算 `hash` 前，将事件对象（**不含 `hash` 字段**）序列化为规范化 JSON 字符串：

1. 对象键按 **UTF-16 码元顺序**（即 JS 字符串默认 `<` 比较 / `Array.prototype.sort()` 默认序）递归升序排列；数组保持原顺序。
2. 不输出任何多余空白（无空格、无换行）。
3. 字符串转义与 ECMAScript `JSON.stringify(string)` 完全一致（`"`、`\`、U+0000–U+001F 按标准转义；非 ASCII 字符原样输出；孤立代理项按 `JSON.stringify` 的 `\uXXXX` 规则处理）。
4. 值域仅使用：字符串、布尔、`null`、整数、对象、数组。核心事件**不使用浮点数**；扩展事件 SHOULD 避免浮点（若使用，必须与 `JSON.stringify` 输出一致，不做精度归一）。
5. 不允许 `undefined`、`NaN`、`Infinity`。
6. 序列化结果按 UTF-8 编码。

### 4.2 哈希

```
hash = "sha256:" + lowerHex( SHA-256( UTF8( canonicalJSON( eventWithoutHash ) ) ) )
```

- `eventWithoutHash` 指删除该事件顶层 `hash` 字段后的对象；其余字段（包括 `prev`、未知字段）都参与计算。
- `prev` 的参与使所有事件串成链：`prev[i] = hash[i-1]`，`prev[0] = ""`。
- 修改任意一行 → 该行 hash 不匹配；删除一行 → 后续行 `seq` / `prev` 不匹配；重排 → 同理。

### 4.3 文件行的写出

写出时**应该**直接输出规范化 JSON（即整行就是 canonical JSON，含 `hash`），便于字节级比对。读取时**必须**重新解析 JSON、按 4.1 规范化后验证哈希，因此手工格式化（加空格、缩进）不会破坏校验，但工具不应这么做。

### 4.4 禁止改写

v1.0 中**任何工具都不得**修改、删除、重排、合并已有行。未来若引入日志压缩（compaction），必须：生成**新文件**；保留原文件到回收站；新文件 header 增加 `compactedFrom` 元数据；不丢弃任何未知字段/事件；且写入完整的新哈希链。该能力属于未来版本，v1.0 实现不得尝试。

## 5. 文本坐标与派生规则

### 5.1 坐标

- 位置 `pos`、长度 `length`、选区 `from`/`to` 一律是 **UTF-16 码元（code unit）偏移**，即 JavaScript 字符串下标；`"😀"` 长度为 2。
- 偏移基于**事件应用前**的派生文本：`0 ≤ pos ≤ text.length`；删除/替换需 `pos + length ≤ text.length`。
- 同一位置的事件必须按 seq 顺序应用。

### 5.2 派生正文（重放）

从 header 开始按 seq 顺序应用所有 `affects = "text"` 的事件：

| 事件 | 作用 |
| --- | --- |
| `text.insert` | `text = text[0..pos) + data.text + text[pos..]` |
| `text.delete` | 校验 `text.slice(pos, pos+length) === data.deleted`，然后删除该区间 |
| `text.replace` | 先校验 `deleted`，再以 `data.text` 替换该区间 |
| `text.reset` | 全文替换为 `data.text`（用于恢复/导入；仍然追加，不改历史） |

- `deleted` 字段**必须**与当时文本完全一致（含代理对、换行符）；不一致 = 非法事件。
- 未知的 `affects = "text"` 事件类型 → 读者必须先声明"无法安全重放"，只读打开并提示升级（见 8.3）。
- `affects = "meta"` 事件不改变正文。
- 快照（`snapshot`）本身不改变正文；它记录当时正文的副本，供加速加载/灾难恢复。

### 5.3 输入法（IME）记录语义

输入法组合期间，正文**尚未确定**。因此：

- `compose.start/update/end` 记录原始的输入法过程（拼音、预编辑串、候选变化），属于 `meta`，**不改变正文**；
- 组合结束、文字真正上屏时，另写一条 `text.replace`（或 insert/delete），`source = "ime"`，精确描述正文变化；
- 组合过程中的撤销/改写只体现在 `compose.update` 的原始数据里，不写正文事件。

这样既有最完整的训练数据（原始拼音/候选），又有干净可重放的正文事件流。`compose.*` 事件的 `data` 可能含用户未上屏的拼音，属敏感数据：应用必须明示记录范围并提供关闭开关（关闭只影响 `compose.*`，不影响正文事件）。

## 6. v1.0 事件类型

> `data` 中未列出的未知字段必须忽略并保留。枚举值只可追加，不可删除（旧读者遇到未知值按默认值降级）。

### 6.1 `doc.init`（header，meta）

见 3.1。**只能是第 1 行**。

### 6.2 文本事件（affects = `"text"`）

所有文本事件共享：

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `pos` | 整数 | 是 | 见 5.1 |
| `source` | 字符串 | 是 | 变化来源，见下表；未知值按 `"unknown"` 处理 |
| `inputType` | 字符串 | 否 | 原样记录 DOM `InputEvent.inputType`（如 `"insertText"`、`"deleteContentBackward"`、`"historyUndo"`），便于训练时区分操作 |

`source` 取值（v1.0）：

| 值 | 含义 |
| --- | --- |
| `typing` | 普通键盘输入 |
| `ime` | 输入法上屏 |
| `paste` | 粘贴 |
| `cut` | 剪切 |
| `drop` | 拖放 |
| `undo` / `redo` | 撤销 / 重做（记最终正文变化） |
| `programmatic` | 程序写入（如自动补全、格式化） |
| `restore` | 版本恢复（配合 text.reset） |
| `recovery` | 损坏抢救/导入修复 |
| `unknown` | 未知来源 |

#### `text.insert`

```json
{
  "seq": 12, "id": "7b1c...", "ts": "2026-10-20T15:33:01.250Z",
  "type": "text.insert", "affects": "text",
  "prev": "sha256:...", "hash": "sha256:...",
  "data": { "pos": 42, "text": "你好", "source": "typing", "inputType": "insertText" }
}
```

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `pos` | 是 | 插入位置 |
| `text` | 是 | 插入的文本；**不得为空字符串**（空插入不得写事件） |

#### `text.delete`

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `pos` | 是 | 删除起点 |
| `length` | 是 | UTF-16 码元长度，> 0 |
| `deleted` | 是 | **被删除的原文**（完整保存，供追回） |
| `direction` | 否 | `"backward"`（退格）或 `"forward"`（Delete 键） |

```json
{"data":{"pos":10,"length":1,"deleted":"字","source":"typing","inputType":"deleteContentBackward","direction":"backward"}}
```

#### `text.replace`

替换一段文本（选中后覆盖、剪切、输入法上屏、撤销等最终结果）。`deleted` 与 `text` 不得同时为空。

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `pos` | 是 | 替换起点 |
| `length` | 是 | 被替换长度（可为 0，等价 insert） |
| `deleted` | 是 | 被替换的原文（length=0 时必须为空串） |
| `text` | 是 | 替换后的文本（可为空串，等价 delete） |

#### `text.reset`

全文重置（版本恢复/导入/抢救）。不得用于普通编辑。

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `text` | 是 | 新的完整正文 |
| `reason` | 是 | `"restore"` / `"import"` / `"recovery"` |
| `targetSeq` | 否 | 恢复到哪个快照 seq（`reason = "restore"` 时记录，便于追溯） |

### 6.3 `session.start` / `session.end`（meta）

用于切分"写作场次"，对训练分身很有价值。

`session.start`：

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `sessionId` | 是 | 会话 ID（UUIDv4） |
| `startedAt` | 是 | 开始时间 |
| `device` | 否 | `{ "platform"?, "userAgent"?, "tz"? }` |
| `editorMode` | 否 | 场次开始时的排版模式 |

`session.end`：

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `sessionId` | 是 | 对应会话 ID |
| `endedAt` | 是 | 结束时间 |

### 6.4 `selection.set`（meta）

光标/选区变化。为实现轻量，应用可节流（如 300ms 或仅在有变化时记录），但**删除事件本身已带位置**，不依赖本事件。

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `from` | 是 | 选区起点 |
| `to` | 是 | 选区终点 |
| `direction` | 否 | `"forward"` / `"backward"` / `"none"` |
| `reason` | 否 | `"caret"` / `"click"` / `"key"` / `"edit"` / `"focus"` / `"programmatic"` |

### 6.5 `editor.mode`（meta）

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `mode` | 是 | `"typewriter"`（打字机：行右端对齐、向左生长）或 `"centered"`（居中：常规排版、光标居中） |

### 6.6 `compose.start` / `compose.update` / `compose.end`（meta）

输入法原始过程（见 5.3）。`data` 字符串为浏览器 `CompositionEvent.data` 的原始值（预编辑串；中文场景常见为拼音/候选串）。**不改变正文**。

| 事件 | 字段 | 必需 | 说明 |
| --- | --- | --- | --- |
| `compose.start` | `data` | 是 | 起始预编辑串（可为空串） |
| | `from` / `to` | 是 | 组合起点/终点（当前正文坐标） |
| `compose.update` | `data` | 是 | 当前预编辑串 |
| | `from` / `to` | 是 | 组合区间 |
| | `candidate` | 否 | 候选序号（能拿到时记录） |
| `compose.end` | `data` | 否 | 结束时的预编辑串 |
| | `committed` | 否 | 最终上屏文本（若与后续 text.* 事件重复，可只做冗余记录） |

### 6.7 `snapshot`（meta）

把当前完整正文副本写入日志，供快速加载、灾难恢复和"版本节点"。**不改变正文**。

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `message` | 否 | 版本说明，如 `"手动保存 15:42"` / 自动保存可省略 |
| `reason` | 是 | `"manual"` / `"auto"` / `"session"` / `"restore"` / `"import"` |
| `text` | 是 | 该 seq 处（本事件不改变正文）派生正文的完整副本 |
| `textHash` | 是 | `"sha256:<hex>"`，对 `text` 的 UTF-8 字节取 SHA-256 |
| `chars` | 是 | `text.length`（UTF-16） |
| `eventsSince` | 否 | 距上一个 snapshot 的事件数 |

**不变量**：在任何合规文件中，重放到该 snapshot 时派生正文必须等于 `data.text`，且其哈希等于 `textHash`。否则文件视为损坏（校验器报告并可用上一快照/前缀抢救）。

### 6.8 `doc.title`（meta）

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `title` | 是 | 新标题（可为空字符串，显示回退"无题"） |

### 6.9 `doc.settings`（meta）

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `changes` | 是 | 部分设置对象，键只增不删；未知键忽略 |

v1.0 已定义键见 6.14。

### 6.10 `doc.trash` / `doc.untrash`（meta）

软删除（进回收站）/ 移出回收站。**不得**物理删除日志数据。

| 事件 | 字段 | 必需 | 说明 |
| --- | --- | --- | --- |
| `doc.trash` | `reason` | 否 | 删除原因（用户备注） |
| `doc.untrash` | `reason` | 否 | 恢复原因 |

### 6.11 `app.checkpoint`（meta，可选）

应用层的外部锚点记录（如"本条事件时已写入备份目录 manifest"）。

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `anchor` | 是 | 被锚定的 `seq` / `hash` 对象：`{ "seq": 整数, "hash": "sha256:..." }` |
| `target` | 是 | 锚点去向，如 `"backup-manifest"` / `"fsa-folder"` |
| `at` | 否 | 锚定时间 |

### 6.12 扩展事件

- 类型名必须以 `x.` 开头，例如 `x.acme.stats`。
- 必须带 `affects`；若扩展改变了正文，必须用 `affects = "text"`（旧读者会因此只读打开并提示升级）。
- 扩展载荷建议放在 `data.ext` 对象内，避免与核心字段名冲突。
- 核心字段名保留：本文出现的所有字段名；`data` 内的 `ext`、`x_` 前缀同样保留给扩展。

### 6.13 `doc.settings.changes` v1.0 键

| 键 | 类型 | 说明 |
| --- | --- | --- |
| `editorMode` | `"typewriter"` / `"centered"` | 文档默认排版模式（应用级设置另存，不写入日志） |

### 6.14 事件与 affects 一览（v1.0）

| type | affects | 作用 |
| --- | --- | --- |
| `doc.init` | meta | header |
| `session.start` / `session.end` | meta | 场次 |
| `text.insert` | text | 插入 |

## 7. 完整性校验与恢复

### 7.1 校验算法（读者必须实现）

1. 解析每一行；空行记警告并跳过；非对象/JSON 解析失败 → 损坏，停止于该行之前。
2. 第 1 行必须是 `doc.init`（`magic`、`format` 合法，`seq = 0`，`type = "doc.init"`）。
3. 对每一行：`seq` 等于上一行 +1；`prev` 等于上一行 `hash`；按第 4 节重算 `hash` 并比对。
4. 按 5.2 重放 `affects = "text"` 事件；所有 `deleted` 必须匹配；位置必须合法。
5. 遇到 `snapshot`：比对派生正文与 `data.text` / `textHash` / `chars`（不匹配记 `snapshotMismatch`）。
6. 遇到未知 `affects = "text"` 类型：停止正常重放，进入只读降级。
7. 全通过 → `ok = true`。

报告必须包含：有效事件数、第一个损坏 seq、损坏原因、未知文本事件、快照不匹配、是否可只读抢救。

### 7.2 恢复（抢救）规则

- 任何损坏都**不得**导致应用静默丢弃数据：必须保留原文件，并在 UI 明示。
- 按"最长有效前缀"派生正文 `OK_TEXT`；若存在早于损坏点的最近合法快照，也可用快照 + 后续合法事件。
- 允许用户把抢救结果导出为新文件（继续使用 `text.reset` 事件追加，不覆盖原日志）。
- 应用层多副本（IndexedDB 主存 + OPFS 镜像 + 可选备份目录）应取"最长且哈希链有效"的副本；副本间分歧不得静默覆盖，生成的恢复报告必须展示。

### 7.3 防篡改说明

哈希链能检测单点修改/删除/重排，但无法阻止"整体重写整条链"的攻击者。因此：

- 备份清单（第 9 节）保存每个文件的 `lastSeq` / `lastHash` / 文件哈希，形成**外部锚点**；
- 应用应在多个物理位置（浏览器存储 + 用户选择的备份目录）保存锚点；
- 威胁模型：防意外损坏、误删、部分数据丢失、普通篡改；不承诺对抗拥有本机完全控制权的恶意程序。

## 8. 兼容性与演进规则（只增不删）

### 8.1 版本号

`format = "主版本.次版本"`：

- **主版本**：破坏性变更（本格式承诺永不发生；若发生，旧文件必须可被新工具导入升级，且升级前保留原件）。
- **次版本**：只做加法。新增可选字段、新事件类型（meta 或 text）、新枚举值、新 source 值。

### 8.2 字段规则

1. 不得删除、改名、改变类型或语义已有字段（**包括未知字段的保留义务**）。
2. 新增字段必须可选，且有明确默认值；旧读者忽略后行为仍正确。
3. 不得复用已废弃的字段名。
4. 枚举只能追加；旧读者遇到未知值必须降级到安全默认（`source → "unknown"`，`mode → "centered"`，`reason` 无默认时忽略事件语义但保留行）。
5. 文本事件不得改变语义；新文本事件类型由次版本引入并声明 `affects = "text"`。

### 8.3 旧读者遇到新内容

| 情况 | 必须行为 |
| --- | --- |
| 未知字段 | 忽略，正常读写 |
| 未知 `affects = "meta"` 事件 | 忽略，正常读写 |
| 未知 `affects = "text"` 事件 | **只读打开**，提示升级；不得写入新事件（否则会破坏正文一致性） |
| `format` 主版本 > 支持的主版本 | **只读抢救**（能解析多少算多少），提示升级；不得写入 |
| `format` 次版本 > 实现的次版本 | 可按 8.3 前两行规则处理；实现应尽量兼容 |

### 8.4 文件身份

- `docId` 由 header 决定且永不变；文件名、标题变更不影响身份。
- 同一 `docId` 的不同文件副本视为同一作品的不同时间点：应用应比较最长合法前缀，短副本可补写合并；哈希分歧时必须报告，不得静默选择。
- 导入时若 `docId` 已存在且内容不同：不得覆盖；应提示"另存为副本"（应用可派生新 `docId` 重建日志，但必须保留原文件）。

## 9. 备份清单格式（`writertools-manifest.json`）

备份目录中的清单，用于多文件备份与外部锚点。本身也遵守"只增不删"。

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `magic` | 字符串 | 是 | `"writertools-backup-manifest"` |
| `format` | 字符串 | 是 | `"1.0"` |
| `createdAt` | 字符串 | 是 | 首次备份时间 |
| `updatedAt` | 字符串 | 是 | 最近备份时间 |
| `app` | 对象 | 是 | `{ "name", "version" }` |
| `docs` | 数组 | 是 | 每个作品一条，见下 |

`docs[]` 元素：

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `docId` | 字符串 | 是 | 作品 ID |
| `title` | 字符串 | 是 | 备份时标题 |
| `file` | 字符串 | 是 | 备份目录内文件名（相对路径，不得含 `..`） |
| `lastSeq` | 整数 | 是 | 备份文件最后一行 seq（外部锚点） |
| `lastHash` | 字符串 | 是 | 备份文件最后一行的 hash（外部锚点） |
| `chars` | 整数 | 是 | 正文 UTF-16 长度 |
| `backupAt` | 字符串 | 是 | 本次写入时间 |
| `fileHash` | 字符串 | 否 | 备份文件整体字节的 `sha256:<hex>` |

- 清单只增不删：作品从库中移除时，清单条目可标记 `trashed: true`，不得删除条目。
- 恢复时以清单锚点校验备份文件是否被截断/改写过。

### 9.1 全量备份包格式（`.wtzip`）

为了"一个文件带走全部作品"，应用支持把全部作品（含回收站）打包成单个 **`.wtzip`** 文件。它是标准 ZIP 容器，**内部日志仍严格遵循本规范 §1–§8，日志格式本身不因打包而改变**。

| 项目 | 约定 |
| --- | --- |
| 扩展名 | `.wtzip` |
| MIME | `application/zip` |
| 容器 | 标准 ZIP；条目名 UTF-8；建议 store 或 deflate |
| 必备条目 | `writertools-manifest.json`（格式见 §9，本文件 `docs[].fileHash` 必须存在）+ 每个作品一个 `<安全标题>-<docId 前 8 位>.wtlog` |
| 其它条目 | 读者必须忽略未知条目；未来可新增（如 README、缩略图），不得删除/改名已有条目语义 |

- `writertools-manifest.json` 中 `docs[].file` 指向 ZIP 内的条目名（相对路径，不得含 `..`）；`lastSeq` / `lastHash` / `fileHash` 是校验锚点。
- 日志条目内容必须逐字节等于对应 `.wtlog` 导出内容（UTF-8 JSON Lines，LF 结尾）。
- 备份包不加密（v1.0）；加密属于未来主版本能力，届时通过新增字段/新扩展名表达，旧读者只读提示。

**导入（恢复/合并）规则**（实现必须遵守，保证"只增不删、不覆盖更新数据"）：

1. 先校验 ZIP 可读、manifest 的 `magic` / `format` 合法；单条目损坏只影响该作品，不得导致整包失败。
2. 对每个作品：读日志 → 按 §7.1 完整校验（哈希链、seq、重放、快照不变量）→ 若清单 `fileHash` 存在还需校验文件整体哈希；失败记 `failed`，保留原文件与本地数据。
3. 与本地比较（按 `docId`）：
   - 本地不存在 → 导入，`imported`；
   - 本地与备份链尾完全相同（`lastSeq`+`lastHash` 相等）→ `skipped`；
   - 本地事件是备份日志的**严格前缀**（链尾 hash 与备份同 seq 事件一致）→ 追加缺失事件，`merged`（只追加，不重写历史行）；
   - 备份是本地日志的前缀（本地更新）→ `skipped`；
   - 相同 seq 处哈希分歧 / 无法判定前缀 → `conflict`，**不写入任何一份**，在报告中列出；
   - 作品正被其它标签页锁定 → `failed`（避免并发写）。
4. 导入不得删除本地作品、不得覆盖更新的本地副本；回收站状态按备份包记录恢复（新导入时）。
5. 导入结束后输出报告：`imported / merged / skipped / conflicts / failed` 计数与逐作品明细。

## 11. 未来预留（不实现，仅确保可加）

以下能力将通过新增字段/事件实现，**不得**改变 v1.0 已有语义：

- **端到端加密**：header 增加 `enc`（算法、KDF 参数）；加密时整行明文会被替换为密文容器——这属于**破坏性**能力，需主版本升级，届时旧文件保持明文可读，新文件旧读者只读提示。
- **按键级原始数据**（keyDown/keyUp、时间间隔）：新增 `x.input.key` 等事件。
- **分支/合并历史**：新增 `parent` 等事件字段；v1.0 线性历史是基础。
- **日志压缩**：见 4.4。
- **云同步状态**：新增 `x.sync.*` 事件（不得写入敏感凭据）。
